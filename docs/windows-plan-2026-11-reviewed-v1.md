## 1. 目標と優先順位

11月の必達目標は、検証基盤の是正、Zig 0.16.0から0.17.0への移行、移行後の実操作・耐久確認とする。
順序は「検証の信頼性確保 → Zig更新 → 日常操作の改善 → 総合検証」。

- P1（最優先）: 移行前の比較基準を確立し、Zig更新と退行検証を行う。
- P2（高）: SSHの操作問題、耐久確認、制約と検証結果の文書化。
- P3（余力枠）: テーマ追従、フォントサイズ継承。移行が長引いた場合は翌月へ回す。
- 条件付き: 実GPU障害の検証。再現環境を用意できない場合は未検証として残す。

上流Ghosttyの[移行PR #14519](https://github.com/ghostty-org/ghostty/pull/14519)と
libxevの[移行PR #249](https://github.com/mitchellh/libxev/pull/249)は2026-10-20にマージ済み。
2026-10-31に確認した上流mainの`build.zig.zon`はZig 0.17.0を指定している。
Windows側の互換性はこれから検証する。着手時に取り込む上流コミットと依存関係を固定し、
Zig 0.18開発版への移行は含めない。

## 3. 実施と検証のルール

- Windows移植・上流機能対応は`windows`で行い、検証後に`gooztty`へ取り込む。
- Gooztty独自の変更と文書は`gooztty`で扱う。`docs/windows-port-log.md`は`windows`でのみ編集する。
- 仕様が未決定の項目は方式決定を先に行い、推測で実装しない。
- `AGENTS.md`とロードマップ第9節に従い、変更範囲に対応した検証を実施する。
- GUIは画面、入力は実操作、ライフサイクルは終了コードと残存プロセスを確認する。
- #50の署名済み配布物による更新・インストール・アンインストール確認は、レモンが作成する成果物で別途行う。
  配布物の確認が残る間は、開発検証完了とIssue全体の完了を区別する。
- 本計画はコミット、タグ、プッシュ、パッケージ作成、公開の実行指示ではない。

## 4. 日程調整と翌月候補

11/13に移行状況を確認し、N05が終わらない場合はN09/N10を延期して移行・実操作検証の枠を確保する。
11/20に退行検証の結果を確認し、未解決の問題を追加機能より優先する。
月末には完了・残件・未検証を分けて記録し、予定日を過ぎただけで完了扱いにしない。

Inspector #18、カスタムシェーダー #14、Undo/Redo #64、Kitten対応 #44は11月の必達範囲外。
その他の未対応設定も、上記作業が完了した後に改めて優先順位を決める。
