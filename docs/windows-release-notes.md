# Ghostty Windows版 リリースノート

Windows版プレビューの公開履歴です。版番号の規則は
[バージョン更新チェックリスト](version-update-checklist.md)、設定と既知の
制限は [利用ガイド](windows.md)、実装状況は
[ロードマップ](windows-roadmap.md) を参照してください。

## 1.3.2-windows.1

- 公開日: 2026-09-15
- タグ: `v1.3.2-windows.1`
- 基準版: upstream Ghostty 1.3.2 系列（開発中の `1.3.2-dev` を基準にした
  最初の Windows プレビュー）
- 位置づけ: プレビュー版。Windows 11 で確認した範囲を対象とし、下記の未確認
  項目を既知の制限として公開する。
- 配布形式: `scripts/build-release.ps1` が生成するポータブルな実行ファイルと
  リソース。インストーラーと自動更新は含まない。署名は配布時に別途行う。

### 同じ版を再現するビルド

```powershell
git checkout v1.3.2-windows.1
./scripts/build-release.ps1 -AdditionalZigArgs '-Dversion-string=1.3.2-windows.1'
./zig-out/release/bin/ghostty.exe --version
```

`--version` とファイルプロパティの `FileVersion` は `1.3.2-windows.1`、数値版は
`1.3.2.1` になります。回帰スクリプトで GPU 復旧と電源復帰を検証する場合は、
`-TestHooks` を付けた別ビルドを使います。配布物には含めないでください。

### 主な内容

- Win32 ネイティブのウィンドウ、タイトルバー、タブバー、分割境界
- D3D11 と DirectComposition による描画、背景透過
- デバイスロストと電源復帰時の GPU 資源自動再作成（タイマー再試行、
  失敗通知、サイクル上限つき）
- 複数ウィンドウ、ネイティブタブ、入れ子の分割ペインと、キーボード・マウス
  双方からの操作
- Windows IME、クリップボード、URL・ファイル操作
- スキャンコードに基づく配列非依存のキー識別と、現在の配列による無修飾文字
- Per-Monitor V2 DPI、ハイコントラスト、MSAA によるタブ情報の公開
- `%LOCALAPPDATA%\ghostty\config.ghostty` の読み込みと再読み込み
- Release ビルドスクリプト、ウィンドウ状態回帰、耐久試験、シェル受け入れ試験、
  起動診断ログの各スクリプト

### 検証

2026-09-15 に Windows 11 Pro（10.0.26200、96 DPI 3台と 120 DPI 1台の
4モニター）で、ReleaseFast・baseline CPU の実行ファイルに対して次を確認しました。

| 項目 | 結果 |
|---|---|
| Release ビルドスクリプトの検証（PE32+、x64、WindowsGui、版情報、アイコン、リソース） | 成功。`FileVersion` 1.3.2-windows.1、数値版 1.3.2.1、`IsDebug` False |
| `--version`、`+list-keybinds --default` | 終了コード 0 |
| ウィンドウ状態回帰（端末入力、設定再読込、分割、4モニター移動、複数ウィンドウ、最大化・最小化・復元、正常終了） | 配布用ビルドで全項目成功、終了コード 0、強制終了なし |
| 同回帰に GPU 資源再作成（制御失敗2回）と電源復帰（3サーフェス）を加えた試験 | テストフック付きビルドで全項目成功 |
| 20 反復の耐久試験（GPU 再作成と制御電源復帰を含む） | 20 プロセスすべて成功、失敗 0、所要 51 秒、一時ファイル残留なし |
| Win32・D3D11・build helpers の単体テスト | 通過 |

Windows シェルの手動受け入れ 6 項目は、アイコン修正版で 2026-09-15 に合格した
結果を引き継いでいます。この版で Alt+Tab、タスクバー、スナップに関わる変更は
ありません。Authenticode 署名は配布時に別途行います。

### 既知の不具合

- `window-width` と `window-height` を設定していると、起動直後の端末グリッドと
  ConPTY が既定の 800×600 相当（約26行）のまま残り、ウィンドウの下側が使われ
  ません。ウィンドウを一度リサイズすると正常になります。原因はコア初期化中の
  `initial_size` によるリサイズ通知が届かないことで、次の版で修正します。
- タグ `v1.3.2-windows.1` を取り出した状態で `-Dversion-string` なしに
  `zig build` を実行すると、ビルドシステムがタグ形式を拒否して失敗します。
  再現手順どおり `-Dversion-string=1.3.2-windows.1` を渡せば成功します。次の版で
  タグ形式を受け付けるようにします。

### 既知の制限

- Windows 10 は未確認です。Windows 11 で確認しています。
- 144 DPI と 192 DPI は単体テストのみで、実機は未確認です。96 DPI と
  120 DPI の混在環境は自動回帰で確認しています。
- 日本語配列以外のキーボード配列は実機未確認です。
- PC を実際にスリープさせた復帰、実際の GPU デバイスロストからの復旧、
  数時間規模の連続稼働は未確認です。Windows の通知を使った制御復帰と、
  20 反復の耐久試験は確認しています。
- Narrator や NVDA による読み上げ、ハイコントラストを実際に有効化した環境の
  表示は未確認です。
- `background-blur` は環境によって品質が変わるため、無効を推奨します。
- インストーラー、自動更新はありません。macOS 版の設定画面や Linux 版の
  GTK 統合に相当する GUI はありません。
- 同一ユーザーの別プロセスが電源通知メッセージを投稿すると、全サーフェスの
  GPU 資源再作成が起きます。表示が一瞬乱れるだけで、セッションは維持されます。
